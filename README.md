# Rust Amigos — игры сообщества

Сайт с играми для сообщества сервера **AMIGOS PVE**: Маджонг, Танчики, общий вход, рейтинги, профиль с украшениями, бот в Discord.

Игра: <https://kut86.github.io/rust-mahjong/>

---

## 1. Как всё устроено

```
Браузер игрока ──► GitHub Pages (статичные файлы: index.html, tanki.html, mahjong.html …)
        │
        └────────► Cloudflare Worker (worker.js) ──► KV  «RATING»  (рейтинги маджонга, сессии, служебное)
                          │                       └─► D1  «DB»      (всё остальное: танчики, инвентарь, босс, профиль)
                          ├─► Steam / Google / Discord (вход)
                          ├─► Discord (слэш-команды и роль бота)
                          └─► ЮMoney (оплата кристаллов)
```

- **Сайт** — обычные файлы на GitHub Pages. Никакой сборки нет: залили файл — через минуту он обновился.
- **Сервер** — один файл `worker.js` в Cloudflare Workers. Он отвечает за вход, рейтинги, награды, босса, инвентарь, оплату, Discord.
- **Игроку не доверяем.** Всё, что даёт награду (волны, убитые враги, урон боссу, задания, кристаллы), проверяется на сервере: время, лимиты, подпись забега, идемпотентные журналы (одну и ту же операцию дважды не засчитать).
- **Таблицы в D1 создаются сами** при первом обращении (`CREATE TABLE IF NOT EXISTS`). Ничего заранее создавать не нужно.

### Файлы репозитория

| Файл | Что это |
|---|---|
| `index.html` | Меню игр, вход (Steam / Google / Discord), профиль, привязка аккаунтов, рейтинг, окно «Украшения и ник» |
| `mahjong.html` | Игра «Маджонг» (уровни в массиве `LEVELS`, награды на уровнях в `REWARD_LEVELS`) |
| `tanki.html` | Игра «Танчики» (весь код одним скриптом): бой, волны, гараж, магазин, инвентарь, задания, бой с мировым боссом |
| `frames.js` | Рамки, украшения и подложки аватаров в рейтинге и профиле |
| `privacy.html` | Политика конфиденциальности |
| `manifest.json`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png` | Установка на экран телефона |
| `img/` | Картинки: танки, скины, предметы, события |
| `worker.js` | Код сервера. **Его нужно вставить в Cloudflare (Deploy)**, на GitHub он лежит только для хранения |

Адрес сервера прописан в начале скриптов `index.html`, `mahjong.html`, `tanki.html` (переменная `API`).

## 2. Развёртывание

1. **Сайт.** Включите GitHub Pages для репозитория (ветка `main`, корень). Любое изменение файла на GitHub публикуется само. После обновления игрокам иногда нужно Ctrl+F5.
2. **Сервер.**
   - Cloudflare → Workers → создайте воркер, вставьте `worker.js`, нажмите **Deploy**.
   - Подключите **KV** с привязкой `RATING` и **D1** с привязкой `DB` (Settings → Bindings).
   - Задайте переменные и секреты из раздела 3 (Settings → Variables and Secrets). Секреты хранятся зашифрованными, переменные видны.
3. **Адрес сервера** впишите в `API` в трёх HTML-файлах, если он изменится.
4. **Discord-команды.** После любого изменения списка команд зарегистрируйте их заново: `https://<воркер>/discord/register?key=<DISCORD_ADMIN_KEY>`.

## 3. Переменные и секреты Cloudflare

«Секрет» — задавайте как Secret, остальные как обычные переменные. Если значение по умолчанию не указано, функция выключена или значение обязательно.

### Обязательные

| Имя | Тип | Что делает |
|---|---|---|
| `SESSION_SECRET` | секрет | Ключ подписи входа и токенов забегов. Длинная случайная строка. Если его сменить, все игроки выйдут из аккаунта |
| `GAME_URL` | переменная | Адрес сайта, на который возвращается игрок после входа (например `https://kut86.github.io/rust-mahjong/`) |
| `GAME_ORIGIN` | переменная | Адрес сайта для CORS (например `https://kut86.github.io`), без слэша на конце |
| привязка `RATING` | KV | Рейтинги, служебные данные |
| привязка `DB` | D1 | Прогресс танчиков, инвентарь, босс, профиль, оплата |

Без этих пяти пунктов воркер отвечает `not_configured`.

### Вход

| Имя | Тип | По умолчанию | Что делает |
|---|---|---|---|
| `STEAM_API_KEY` | секрет | нет | Ник и аватар Steam. Без него вход работает, но имя игрока может быть пустым |
| `GOOGLE_CLIENT_ID` | переменная | значение в коде | Идентификатор приложения Google для входа |
| `DISCORD_CLIENT_ID` | переменная | нет | Вход через Discord и бот |
| `DISCORD_CLIENT_SECRET` | секрет | нет | Вход через Discord |

Аккаунты разных способов входа можно объединить через привязку в профиле. Номер аккаунта общий: Steam-аккаунты используют свой Steam id, Google начинается с `g`, Discord с `d`.

### Сезоны (сброс без удаления данных)

Сменили значение, и рейтинг или прогресс начинается заново; старые данные остаются в базе. Допустимы буквы, цифры, `-` и `_`, до 20 символов. По умолчанию сезон `1`.

| Имя | Что сбрасывает |
|---|---|
| `MJ_SEASON` | Рейтинги маджонга (прохождения и скорость) |
| `TANK_RATING_SEASON` | Рейтинг танчиков (волны, очки, боссы) |
| `TANK_PROGRESS_SEASON` | Прогресс игроков в танчиках: монеты, танки, уровни. Игра сама сбрасывает локальный прогресс при смене значения |

Промокоды маджонга и инвентарь (ключи, сундуки, кристаллы) от сезонов **не зависят**.

### Маджонг

| Имя | По умолчанию | Что делает |
|---|---|---|
| `TOTAL_LEVELS` | 5 | Сколько всего уровней. Должно совпадать с числом уровней в `LEVELS` в `mahjong.html` |
| `MIN_SECONDS` | нет | Минимальное время до прохождения каждого уровня, через запятую (защита от подделки). Слишком быстрое прохождение даёт ошибку `too_fast` |
| `PROMO_1` … `PROMO_N` | нет | Промокод за прохождение N-го уровня. Пусто — награды нет |
| `PROMO_N_UNTIL` | нет | Дата окончания промокода `ГГГГ-ММ-ДД` (до конца этого дня). После неё код пропадает |

Чтобы дать награду на нужном уровне, укажите его в `REWARD_LEVELS` в `mahjong.html` и задайте `PROMO_N`.

### Танчики: рейтинг волн

| Имя | По умолчанию | Что делает |
|---|---|---|
| `TANK_WAVE_SECONDS` | 12 | Минимум секунд на одну волну. Волна N засчитывается не раньше чем через N × это число секунд после старта забега |

### Мировой босс

| Имя | По умолчанию | Что делает |
|---|---|---|
| `BOSS_RATE` | 300 | Сколько урона даёт 1 монету |
| `BOSS_DAY_CAP` | 0.15 | Дневной лимит урона одного игрока как доля здоровья босса |
| `BOSS_CAP_K` | 1.2 | Запас к максимально возможному урону за бой (проверка на накрутку) |
| `BOSS_MAX_SEC` | 120 | Длительность боя с боссом, секунд |
| `BOSS_PRICES` | 1000,1500,2250 | Цены платных сбросов попыток в монетах (каждый сброс дороже) |
| `BOSS_GEM_PRICES` | 15,25,40,60,90 | Цены докупки попыток за кристаллы, до 5 штук в день |
| `BOSS_AWARDS` | в коде | Необязательно, JSON: правила выдачи рамок за босса. **Если задана, заменяет встроенные правила** |
| `BOSS_ADMIN_IDS` | нет | Через запятую: номера аккаунтов или Discord id администраторов босса. Им также разрешены ники со словом «Админ» |

Остальное задаётся при создании босса: здоровье (по умолчанию 100 000), длительность (7 дней), минимальный и максимальный уровень танка (по умолчанию от 8), попытки (по умолчанию 3 в день) и число платных сбросов (по умолчанию 3).

### Инвентарь, кристаллы, ники и задания

| Имя | По умолчанию | Что делает |
|---|---|---|
| `INV_STARTER` | 3 | Сколько щитов, залпов и двойных стрельб получает новый игрок |
| `CHEST_GEMS` | 30 | Цена сундука в кристаллах |
| `KEY_GEMS` | 20 | Цена ключа в кристаллах |
| `NICK_GEMS` | 50 | Цена смены ника (первая смена бесплатна) |
| `DQ_KEY_CHANCE` | 0.5 | Шанс ключа за выполнение всех трёх ежедневных заданий (0–1) |

Прочие значения лежат прямо в коде `worker.js`:

- Содержимое сундука (`CHEST_LOOT`): золото 10–200, щит 4%, залп 3,5%, двойная стрельба 3,5%.
- Падения с босса (`BOSS_DROP`): ключ с шансом 30% (не больше 6 на босса), кристаллы с шансом 25% (1–10 штук).
- Ежедневные задания (`DQ_POOL`): список заданий и награды в золоте.
- Рамки, украшения, подложки (`COS`, `BOSS_AWARDS`).
- Часовой пояс начала дня `UNTIL_UTC_OFFSET_H` = 5 (Алматы).

### Discord

## 4. Что есть в играх

### Маджонг
Уровни задаются массивом `LEVELS`. Прохождение отправляется на сервер, который проверяет время (`MIN_SECONDS`). Рейтинги: прохождения и скорость. За выбранные уровни выдаётся промокод (`PROMO_N`).

### Танчики
- **Бой с волнами.** Рейтинг: волны, убитые враги, очки, боссы волн. Данные отправляются сервером-проверяемыми отчётами забега.
- **Гараж и танки.** Танки трёх классов (лёгкие, средние, тяжёлые), модули, навыки, склад снарядов.
- **Облачное сохранение.** Прогресс хранится в D1 по разделам (танки, опыт, модули, навыки, боезапас, волны); монеты ведутся журналом операций. Защита от старых вкладок: сервер знает версию раздела.
- **Инвентарь.** Ключи, сундуки, кристаллы, щит, залп, двойная стрельба. Сундук открывается ключом; ежедневный бесплатный сундук ключа не требует.
- **Магазин.** Сундуки и ключи за кристаллы. Кристаллы пополняются через ЮMoney.
- **Ежедневные задания.** Три задания в день, одинаковые для всех, прогресс считается сервером по проверенным отчётам боёв. За каждое золото, за все три бонус «шанс ключа».
- **Мировой босс.** Один общий враг на всех. Урон копится за все дни, в день есть лимит и 3 попытки; сбросы попыток за монеты, докупка за кристаллы. За каждые `BOSS_RATE` урона даётся 1 монета; с босса падают ключи и кристаллы. Награды (рамка, украшение, подложка) выдаются после победы всем, кто бил босса.

### Профиль и украшения
- Ник можно сменить: первый раз бесплатно, дальше за кристаллы. Фильтр: длина 3–16, буквы/цифры/пробел/`_ . -`, антимат (в том числе замена похожих букв), зарезервированные слова (`админ`, `admin`, `модер`, `support`) доступны только админам.
- **Роли в карточке игрока.** Внизу карточки показываются «таблетки» ролей: «Администратор» (аккаунт из `BOSS_ADMIN_IDS`), «Бета-тестер» (получил роль от бота) и роли на вашем Discord-сервере (берутся через бота, нужны `DISCORD_BOT_TOKEN` и `DISCORD_GUILD_ID`, цвет как у роли в Discord). Роли Discord кэшируются на 5 минут. Роль «бета тестер» не дублируется. Если у игрока нет ролей, блок не показывается.
- Четыре слота: **аватар**, **рамка** вокруг аватара, **украшение** (молнии вокруг) и **подложка** всей строки в рейтинге.
- **Аватары.** Игрок не может загрузить свою картинку, а выбирает из набора, который вы положили в папку `img/avatar/` репозитория. Аватар создаётся так же, как остальные украшения: вкладка «Украшения» → «Новое украшение» → вид «Аватар», выбираете картинку из списка. Выдача такая же: вручную игроку или автоматически за событие. Пункт «Свой» в окне выбора возвращает аватар из аккаунта (Steam, Google или Discord).
- **Доступные всем и заглушка.** У аватара две галочки. «Доступен всем» добавляет его в список каждого игрока (можно сделать сколько угодно таких). «Заглушка по умолчанию» отмечается у одного аватара: его видят все, кто ничего не выбрал (она сама включает «Доступен всем», а у прежней заглушки отметка снимается). Если заглушка не отмечена, берётся аватар с кодом `default`, иначе первый из доступных всем по алфавиту. Остальные аватары (без галочек) выдаются вручную или за события. Картинки из аккаунтов (Steam, Google, Discord) не показываются никому; выбранный аватар виден в шапке, рейтинге, карточке игрока и на боссе.
- Адрес картинок на сайте берётся из переменной `SITE_URL` (по умолчанию `https://kut86.github.io/rust-mahjong/`).
- **Новое украшение — из игры, без кода** (раздел «Админ-панель» ниже): вкладка «Украшения» → «Новое украшение». Выбираете вид (рамка, украшение, подложка), цвета, эффекты и картинку, внизу сразу видно, как оно выглядит.
- Картинки лежат в папке `img/cos/` репозитория (png, webp, gif, jpg, svg). Загрузите файл на GitHub и нажмите «↻» рядом со списком картинок. Для рамки лучше PNG с прозрачной серединой, для украшения (крылья, нимб) прозрачный PNG, для подложки широкая полоса или узор (в карточке рейтинга она повторяется на каждой строке).
- Выдача: из той же вкладки игроку по нику или номеру аккаунта, либо автоматически за победу над боссом: в форме события отметьте украшения для «всем, кто бил», «топ-1», «топ-2», «топ-3».
- Старый способ (в коде): 1) строка в `COS` в `worker.js` (`'fr:имя'`, `'dc:имя'` или `'bg:имя'`), 2) запись с тем же именем в `frames.js` (`FRAMES`, `DECOS`, `PLATES`), 3) при необходимости правило в `BOSS_AWARDS`. Подробная инструкция в шапке `frames.js`.

## 5. Админ-панель в игре

Видна только аккаунтам из `BOSS_ADMIN_IDS`. Включается галочкой «Админ-режим» в окне «Украшения и ник» (меню игр, нажать на себя). После этого в «Танчиках» на главном экране появляется кнопка «⚙ Админ» с четырьмя вкладками:

| Вкладка | Что делает |
|---|---|
| Танки | Меняет ТТХ любого танка (здоровье, скорость, урон, перезарядка, рикошет, броня, пробитие, калибр, вес, название). Правки хранятся на сервере и действуют у всех игроков |
| Боты | ТТХ врагов с теми же полями, что у танка игрока (здоровье, скорость, поворот башни, урон за выстрел, перезарядка, рикошет, броня, пробитие, вес), по классу и ступени: 30 строк (ЛТ/СТ/ТТ × 1–10). Не зависят от вкладки «Танки»: правки танков игрока на ботов не влияют, а правки ботов не влияют на игрока. Значения потом множатся на тип врага (разведчик, снайпер, босс). Перезарядка и поворот башни меняют темп врага пропорционально заводскому значению, рикошет по умолчанию 0 (отражает часть попаданий в лоб). Калибра нет: он нужен только для цены снарядов игрока. Хранятся в `tk_tstats` с кодом `bt:<класс><ступень>`, например `bt:m3`. |
| Типы врагов | Типы врагов и боссы. Для каждого типа (лёгкий, очередник, средний, минёр, тяжёлый, снайпер, ремонтник, босс волны) задаются множители здоровья, урона, скорости, брони, пробития и веса, перезарядка, очки, волна появления и доля в волне. Способности: у минёра урон и время жизни мины, число мин; у снайпера время прицеливания, дальность, скорость снаряда и лимит одновременно (до и после 40-й волны); у ремонтника частота и дальность лечения и лимит; у очередника число выстрелов в очереди; у босса волны порог ярости, перезарядка в ярости, число призываемых и их лимит. Отдельная строка «Мировой босс»: броня, сопротивление фугасам, урон и паузы разрядов, урон, скорость и перезарядка выстрела. Хранятся в `tk_tstats` с кодом `ty:<тип>` (`s Q n M h Z R B W`). Пустое поле возвращает заводское значение. |
| Босс волны (в «Типах врагов») | У босса волны своя таблица ТТХ по ступеням 1–10 (здоровье, урон, скорость, броня, пробитие, вес, рикошет), не связанная со строкой СТ на вкладке «Боты». Босс берёт строку по ступени, которая зависит от волны и класса танка игрока. Заводские значения равны прежним (строка СТ × старые множители босса), бой не меняется. Хранятся в `tk_tstats` с кодом `bb:<ступень>`. Ниже в той же форме способности и появление (пауза между залпами, очки, порог ярости, перезарядка в ярости, число призываемых и их лимит). Множители здоровья, урона и т.п. для босса больше не используются. |
| События | Создать, изменить, остановить, запустить, удалить босса или объявление; изменить здоровье; задать награды-украшения за победу |
| Цены | Цены сундука, ключа, смены ника, сбросов и докупки попыток босса, курс урона, дневной лимит, шанс ключа за задания, кристаллы за рубль и другие. Перекрывают переменные Cloudflare (пустое поле возвращает стандарт) |
| Украшения | Создать рамки, украшения и подложки, выдать или забрать у игрока |

Права проверяет сервер при каждом запросе, кнопка в игре только удобство. Данные админки лежат в таблицах D1: `tk_tstats` (ТТХ), `tk_cfg` (цены), `tk_cosdef` (украшения), поле `aw` в `tk_event` (награды события).

## 8. Частые проблемы

- **`not_configured`** — не заданы `SESSION_SECRET`, `GAME_URL`, `GAME_ORIGIN` или привязка `RATING`.
- **Изменения не видны на сайте** — GitHub Pages обновляется до минуты; сделайте Ctrl+F5. Не заливайте файлы слишком часто: при частых запросах GitHub временно отвечает 429.
- **Новая команда Discord не появилась** — заново откройте `/discord/register?key=…`.
- **Платёж не пришёл** — откройте `/pay/last?key=…`, проверьте метку `rm:…` и секрет `YM_SECRET`.
- **Босс: «танк не соответствует»** — проверьте диапазон уровней события и что танк есть в таблице `BOSS_TANK` в `worker.js`.
- **Ник «зарезервирован»** — слова `админ`, `admin`, `модер`, `support` разрешены только аккаунтам из `BOSS_ADMIN_IDS`; слова `amigos` и `amigo` разрешены всем.
- **Рамки за босса не выдались** — проверьте, что босс побеждён; для уже побеждённого запустите `do=award`; проверьте, не задана ли переменная `BOSS_AWARDS` без нужных предметов.

## Роли (награды и роли Discord)
- Админка → «Украшения и роли» → вид **Роль**: название, цвет, значок (эмодзи) и необязательная связь с ролью Discord (кнопка «Подтянуть роли с сервера» берёт список у бота).
- В карточке игрока показываются **все его роли Discord** (кроме служебных) и роли, выданные в игре. Роль, оформленная в админке и связанная с Discord-ролью, показывается в вашем оформлении. «Не показывать отдельно» скрывает связанную роль Discord.
- Роль, выданная в игре (вручную или наградой за босса), выдаётся и в Discord, если у игрока привязан Discord; при «Забрать» снимается. Бот должен стоять в списке ролей сервера выше выдаваемой роли и иметь право «Управление ролями».
- Бета-тестеры: создайте роль и свяжите с ролью «бета тестер»; кнопка «Всем бета-тестерам из базы» выдаёт её тем, кого уже отметил бот (повтор безопасен).
- Вкладка **Выдача**: украшения, роли, кристаллы, ключи, сундуки, щиты, залпы, двойная стрельба (отрицательное число — забрать). Игрок — ник, имя в рейтинге или номер аккаунта. Журнал последних выдач внизу. Золото хранится в игре у игрока, выдать его отсюда нельзя.
- Вкладка **Роли**: создание и правка ролей. У роли отмечаются **украшения обладателям** — они автоматически достаются всем, у кого роль есть (выдана в игре, есть в Discord, или бета-тестер из базы); выдаётся при открытии профиля игроком. Кнопка «＋ Создать роль в Discord» создаёт роль на сервере (нужно право бота «Управление ролями»). Снятие роли украшения не отнимает.
- Когда роль забирают (кнопка «Забрать» или потеря роли в Discord), вместе с ней забираются украшения, выданные именно этой ролью, и снимаются с игрока, если надеты. Украшения, выданные вручную или наградой, остаются. Если у игрока та же вещь приходит от другой роли, которая у него осталась, она не отнимается. Если Discord не ответил, ничего не отнимается.
- Роли строго раздельны: роль не достаётся никому, пока её не назначили (в игре, в Discord или связанной Discord-ролью). Одна Discord-роль связывается только с одной игровой ролью. Кнопка «🧪 бета» есть только у роли, связанной с Discord-ролью бета-тестера. В списке ролей показано, скольким игрокам роль выдана.
- Три галочки у роли: **Скрыть в профиле** (роль не показывается в карточке игрока), **Роль-награда** (можно давать за события и выдавать вручную; без галочки роль нигде не выдаётся из игры) и **Запретить выдачу из игры** (например «Админ»: ни игра, ни бот не выдают и не снимают эту роль, ни в игре, ни в Discord; перекрывает «Роль-награда»).
- У каждой роли кнопка 👥: список тех, у кого роль записана в игре, с источником (вручную, кнопка «бета», награда, от роли). «Убрать» и «Убрать у всех» стирают запись в игре и украшения этой роли, **в Discord ничего не меняется**. Счётчик в списке — число записей в игре, а не людей с ролью в Discord.
- **Правка в гараже (админ).** В карточке танка кнопка «✎ Править»: «✎ Править ТТХ танка» открывает базовые характеристики (те же, что во вкладке «Танки»), нажатие на блок Ур. 2/Ур. 3 орудия, башни, двигателя или гусениц открывает его множители с живым предпросмотром итоговых цифр. Множители блоков общие для всех танков (хранятся как `mp:<модуль><уровень>`), ТТХ — у конкретного танка. Ур. 1 («сток») берётся из ТТХ танка.
- **Цены в гараже (админ).** В «✎ Править ТТХ танка» — цена открытия танка (монеты и опыт на предыдущем танке; у танка I ступени только монеты). В правке блока Ур. 2/Ур. 3 — цена этого блока для этого танка (опыт и монеты). Пустое поле/значение по умолчанию — цена по формуле. Цены навыков, снарядов и скинов пока не правятся.
- Множители блоков (Ур. 2/Ур. 3) теперь **у каждого танка свои**: правка блока одного танка другие танки не меняет. Хранятся в правках танка как `<модуль><уровень>_<параметр>` (например `g2_dm`), без правки действует стандартный множитель.
- Вкладка «Танки» убрана из админ-панели: ТТХ, цены и блоки танков правятся только в гараже (режим «✎ Править»). Остальные вкладки: Боты, Типы врагов, События, Цены, Украшения, Роли, Выдача. Сохранённые правки танков в базе остаются и работают.
- **Боекомплект и снаряды в гараже (админ).** В режиме «✎ Править» кнопка «✎ Боекомплект и снаряды»: вместимость боекомплекта танка, а для каждого снаряда (ББ, БП, ОФ) множители урона и пробития и цена за 100 шт. Всё только для этого танка; пустое значение или стандартное — по формуле. Хранится в правках танка (`ac`, `s<тип>_dm|pn|pp`).
- **Калибр орудия и склад снарядов.** У каждого уровня орудия танка есть подпись калибра (`gc1`–`gc3`): Ур. 1 — в «✎ Править ТТХ танка», Ур. 2/3 — в правке блока орудия. Подпись начинается с числа (мм): «76 мм», «76 мм Ф-34». Пробитие растёт пропорционально калибру относительно стокового орудия, урон — пропорционально квадрату калибра; цена снарядов — пропорционально калибру. Снаряды подходят только под калибр установленного орудия; склад общий для всех танков с одинаковой подписью. При смене орудия снаряды старого калибра уходят на склад и лежат там, пока игрок сам не продаст их (50% цены). Вместимость боекомплекта задаётся админом по каждому танку отдельно. Старый склад по танкам при первом входе переносится на склад по калибру.
- Вкладки админки «События» (объявления: название, текст, длительность) и «Мировой босс» (здоровье, уровни танков, попытки, сбросы и цены, награды) раздельные; данные и серверное API те же.

## Вкладка «Экономика»
Админка → Экономика: награды за бой (опыт/монеты за очки, рост за ступень врагов, минимум на слабых волнах, бонус за новую волну), цены по умолчанию (открытие танков, модули, обмен, ремонт) и калькулятор дохода за забег. ## Поддержка, баны и сбросы
- **Игрок:** кнопка «✉ Поддержка» в профиле (index.html) и под ником в Танчиках. Тема из списка + текст до 300 символов. Пока администрация не прочитала обращение, новое отправить нельзя. Игрок видит статус «Ждёт» / «Прочитано».
- **Фиксируется:** ник, номер аккаунта, привязки (Steam / Google / Discord), время (в админке показывается по Алматы; пояс — константа `ADM_TZ` в tanki.html).
- **Админка → «Поддержка»:** список обращений (счётчик новых на кнопке «Админ» и на вкладке), «Прочитано», «Удалить», переход к игроку. Вкладка «Игрок и наказания»: сводка, бан (1/7/30 дней или навсегда + причина), снятие бана, сброс рейтинга (Танчики / Маджонг / оба), сброс прогресса Танчиков, откат из копии. Админов банить нельзя.
- **Бан:** закрывает весь сайт, остаётся только форма поддержки; игрок скрывается из рейтингов. Проверка кэшируется на 30 с.
- **Сбросы** необратимы, но перед каждым сохраняется копия (таблица `sup_bak`), её можно вернуть. После сброса прогресса игра на устройстве игрока сама сбрасывает локальное сохранение (эпоха `sup_ep`), чтобы старые данные не вернулись.
- Таблицы: `sup_tk`, `sup_ban`, `sup_ep`, `sup_bak` (создаются сами). Все действия пишутся в журнал `adm_log`.

### Выборочный сброс прогресса
Кнопки в карточке игрока: «Лёгкие / Средние / Тяжёлые» (сами танки класса, их опыт, модули, навыки, боекомплект и рекорд волн; стартовый l1 остаётся, скины не трогаются), «Все танки» (то же для трёх классов и склад снарядов), отдельно «Опыт», «Монеты», «Снаряды», «Скины» и «Сбросить всё» (скины и 💎 не затрагивает). Донатная валюта и инвентарь лежат в других таблицах и не затрагиваются. Склад снарядов общий по калибру, поэтому сброс одного класса его не трогает. Устаревший клиент после сброса получает `stale` и перезагружает прогресс, а не затирает его.
